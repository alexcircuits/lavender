Fixture mode offers the Wildfires layer only when a FIRMS key is set, although it reads
`firms.csv` and contacts no upstream. The harness sets the placeholder
`LAVENDER_FIRMS_MAP_KEY=perf-fixture-placeholder` and removes every inherited `LAVENDER*`
variable, so both server phases run exactly the recorded configuration.

**Cold and warm.** Browser: every scenario starts in a fresh context with the network cache
disabled through CDP (GEV's startup condition); the server was already running and its
fixture files were in the OS cache. Layer activation is the first subscription to that
feed on the server, except in the five-layer scenario, where the aircraft, satellite and
fire slots were still lingering from the scenarios before it. Load test: one cold request
per route (it fetches from the fake upstream, or reads and parses the fixture file), then
warm measurements.

**Sample sizes.** Startup: 3 runs, medians. Scenes: one 5 s rest window, 2 s of unrecorded
warm-up motion, then three 5 s motion windows, median. Keyed updates: 3 refreshes of 10 000
moved contacts. Load: 5 s on one connection and 10 s on 32 connections per route; fan-out
over a 30 s window (5 s cadence) × 100 subscribers per cell. Benchmarks: criterion, 100
samples (30 for the 10 MiB parsers), 95 % intervals.

The bbox test itself is cheap: a linear scan of 50 000 points takes 19–39 µs, and an R-tree
saves at most a few tens of microseconds per query for 7 ms of building per refresh. The
cost is around it. The hub's snapshot of the same 50 000 aircraft takes 10.5 ms even for a
city box with nothing in view, because `filter_items` (`hub/snapshot.rs`) first
de-duplicates every item (a `String` key, a `HashSet` insert and a clone of each aircraft)
and only then applies the bbox and the cap. Measured as the hub uses it, the "bbox filter
of 50 000 points" target is unmet by about five times.

## Findings

1. **Dense worldwide snapshots miss the 5 ms target.** One connection, p95: 32.8 ms for
   20 000 aircraft (7.3 MB), 71.2 ms for fires (100 000 detections, 2 017 cells), 6.5 ms for
   5 000 satellites, and 9.3 ms for a Europe box out of 20 000 aircraft. Under 32
   connections the server answers 187 worldwide aircraft or 74 fires snapshots per second.
   Every GET composes the snapshot again (finding 2), and the handler encodes it to JSON
   twice, once for the `ETag` hash and once for the body (`routes.rs`, `feed`); the
   worldwide aircraft encoding alone is 7.5 ms.
2. **The hub's filter path costs 10.5–18.7 ms for 50 000 aircraft, the bbox test 19–39 µs.**
   `hub/snapshot.rs` `filter_items` builds a `String` key, inserts it into a `HashSet` and
   clones every item before it applies the bbox, the attribute filters and the cap. For
   fires the key is a formatted string of about 100 characters per detection. The bench
   `crates/lavender-core/benches/snapshot.rs` measures any change.
3. **Normalisation misses its target** (72.6 ms USGS, 67.5 ms adsb.lol for 10 MiB; target
   50 ms). Both parsers deserialise every row into a `serde_json::Value` and then into the
   typed row (`providers::parse_rows`), and every lenient field once more through a `Value`
   (`providers::lenient`). The benches in `crates/lavender-core/benches/normalise.rs`
   measure any change.
4. **WebSocket fan-out misses its target for busy cells** (19.6 ms for 100 subscribers of a
   361 KB snapshot; 0.3 ms for the 10-contact control). Each subscription composes and
   encodes its own copy of the snapshot, so one cycle writes about 36 MB.
5. **Unchanged snapshots are re-sent after camera moves.** The web client sends an `update`
   frame after camera moves even when its worldwide query is unchanged, and the server
   answers every `update` with the full snapshot. In the aircraft scenario 7 re-sends
   carried 36.6 MB with no new data, and each was parsed and re-applied (about 13 ms of
   main thread each).
6. **Memory with dense populations.** With every fixture feed active and idle (20 000
   aircraft, 5 000 satellites, 100 000 fire detections, earthquakes, cyclones) the server
   held 137.8–196.7 MiB RSS, around the 150 MiB target; after 32-connection worldwide GETs it
   held 550–664 MiB. These are point samples; what holds the memory was not analysed.
7. **Long tasks at activation.** Turning satellites on blocks the main thread for 46 ms and
   the 10 000 → 20 000 aircraft refresh for 45 ms: each drops two or three frames.
8. **The five-layer scene's motion dips.** Its first motion sample measured 38.7 fps (run A)
   after the warm-up, with 50 ms frame gaps; in run A no other scene dipped (in run B the
   20 000-aircraft scene and one startup run each had one sample near 49 fps). The stream frames
   that arrived in the dipping samples were fires snapshots (run A) and earthquake, aircraft
   and fires snapshots (run B). The re-sent snapshots after each camera move (finding 5) are
   a candidate; a profile of that scene would settle it.
9. **Fixture mode needs provider keys.** Wildfires reports "Not configured: NASA FIRMS map
   key" in fixture mode unless `LAVENDER_FIRMS_MAP_KEY` is set, although fixture mode reads
   a file and contacts no upstream. The harness sets a placeholder.
10. **The capture machine was busy.** Run B, 15 minutes after run A, shows how far the
    numbers move: 376 ms instead of 76 ms first paint, and up to four times the dense
    snapshot p95. Repeat
    on a quiet machine before using these numbers as acceptance evidence for ENG-974 or
    ENG-976.

## Changes since the first run

The first run of this capture (2026-10-15 21:25–21:42 UTC) reported "Met" for the cached
snapshot and the bbox filter, measured on a 45-event feed, one 1 000-contact cell and a
`BBox::contains` micro-benchmark; it left FIRMS and the five-layer heap unmeasured because
the harness did not set a FIRMS key for fixture mode; and it sampled the combined scene
without warm-up. After review the harness gained the hub snapshot bench, the load test's
dense fixture phase and the fan-out control cell, sets the FIRMS placeholder and removes
inherited `LAVENDER*` variables, warms motion up for 2 s before sampling, and fails a
scenario whose layer the catalog does not offer instead of skipping it. Its figures under
heavier load (for example 102.9 ms for adsb.lol normalisation) are superseded by the ones
above.
